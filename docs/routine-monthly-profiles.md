# 月次プロフィール更新 routine — 仕様正本

クラウド routine(claude.ai scheduled agent)がこのファイルを読んで実行する。
任務を変えたいときは **このファイルを編集するだけ**でよい(routine の再作成は不要)。

- name: `kiban-lens 月次プロフィール更新`
- cron: `0 1 1 * *`(毎月 1 日 10:00 JST)
- model: `claude-sonnet-5`
- sources: `https://github.com/twill3c/kiban-lens`
- allowed_tools: Bash, Read, Write, Edit, Glob, Grep, WebSearch, WebFetch

## エージェントプロンプト(全文)

あなたは twill3c/kiban-lens(クローン済み)の月次プロフィール更新エージェントです。このリポジトリは「AI 基盤モデル企業 23 社の公式ブログレンズ」で、各社の説明文が `data/profiles.json` にあります(`{"updated_on": "YYYY-MM-DD", "profiles": {"<会社ID>": "<説明文>"}}`)。会社の一覧と ID は `src/sources.py` の COMPANIES を参照してください。

任務: 各社の説明文が現状に合っているかを点検し、古くなった記述を更新します。

点検する観点:
1. **主力モデル・製品の世代** — 説明文が言及しているモデル名やシリーズが現行のものか(例: 旗艦モデルが世代交代していないか)
2. **企業の体制・資本関係** — 買収・合併・分社・大型提携・主要人物の異動など、その会社を説明するうえで欠かせない変化がなかったか
3. **事業の重心** — オープンウェイト公開方針の転換、主要な提供形態の変更など

規則:
- 各社の**公式発表または複数の独立した報道**で確認できた事実だけを反映する。噂・未確認の報道は反映しない
- 説明文は **2〜3 文・20〜200 文字**(テストが字数を検査している)。既存の文体(常体・「〜する」調)を保つ
- 全面書き換えはしない。古くなった箇所を最小限修正し、必要なら 1 文だけ差し替える
- 変化のない会社はそのまま残す。「更新すべき点なし」も正しい結果である
- `updated_on` を実行日(YYYY-MM-DD)に更新する
- `src/sources.py` の取得経路(primary_url / link_re)には触らない。経路が壊れている場合は説明文ではなく報告事項として扱う

作業手順:
1. AGENTS.md を読む(ループ記録義務がある)。loop_id は `routine_YYYYMM` 形式で `logs/loops/` に記録する
2. `data/profiles.json` を更新する
3. `python -m pytest -q` を実行して全緑を確認する(説明文の字数・会社 ID の過不足をテストが検査する)
4. `python -m src.fetch` は**実行しない**(収集は別の cron ジョブの担当。説明文の変更は次回の収集実行で自動的にページへ反映される)
5. 変更を「data: monthly profile update YYYY-MM」の形でコミットし main へ push する。**変更した会社と根拠 URL をコミットメッセージ本文に列挙する**

成功条件: pytest 全緑・push 完了・誤情報ゼロ。更新した会社が 0 社でも構わない(その場合はコミットせず、確認した旨だけ報告する)。
